The RPG NeuralMesh API

NeuralMesh answers questions across the RPG companies from each company's own node, and keeps the context graphs people ingest as JSON. This page lists every route with its request and answer, shows how to query a context graph, and gives real requests and answers to try.

How to access NeuralMesh

Highlights

  • 49 REST routes in 7 groups (health and sign-in 5, ask and search the mesh 11, links, governance and the dashboard 9, uploaded context graphs 14, ingested context graphs 7, help 1, applications: the context contract 2), listed on All routes.
  • People sign in and send the token they get. Applications send a service token and one envelope to the 14 tools of the context contract, 13 of which AI agents also reach over MCP.
  • An ingested context graph is queried by its id in seven ways: overview, nodes, node, edges, path, similar and a question in plain words.
  • Every answer is scoped to the caller: a graph with sharing company answers 404 to other companies, and never-leave items stay with their company.
  • 35 of the 49 routes and 12 of the 14 tools (ask, entity, find_mentors, inspection_history, inspection_profile, learning_sources, live, related, role_context, similar, skill_context, vocabulary_export) were sent to the running development API on 11 November 2026. The routes that change data were not sent. Every answer on this page is one the API gave, on invented data.

A service token also opens the ingested context graph routes: its company is group, so it reads the graphs shared with the group and cannot ingest. The company nodes answer the centre only. Their tools are listed at the end of All routes.

Start in three calls

1. Sign in. The answer holds access_token.

curl -s -X POST 'http://127.0.0.1:8000/api/v1/auth/signin' -H 'Content-Type: application/json' -d '{"email": "presenter@neuralmesh.local", "password": "<password>"}'
TOKEN=<the access_token of the answer>

2. Ask the mesh a question.

curl -s -X POST 'http://127.0.0.1:8000/api/v1/mesh/query' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"question": "What rubber-compound learnings from CEAT could reduce Harrisons Malayalam'\''s latex spoilage?", "purpose": "problem_solving"}'

3. Query a context graph by its id. The id comes from GET /api/v1/context-graphs or from the answer of the ingest.

curl -s -X POST 'http://127.0.0.1:8000/api/v1/context-graphs/cg-1cc11e1e/query' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"path": {"from": "Supplier X", "to": "Plant A"}}'

The API also describes itself at http://127.0.0.1:8000/docs: open it in a browser, press Authorize, paste the token, and every route can be sent from there.

Rules every call follows

  • Bodies and answers are JSON, except the file of an upload (a form) and a download with format.
  • The token goes in Authorization: Bearer <token>. A person's token is valid for 12 hours.
  • 200 or 201 is a good answer. 401 is a missing or expired token, 403 a role the route needs, 404 an id that is not there or not shown to the caller, 409 a name that fits several nodes, 413 a body over 8,000,000 bytes, 422 a field to fix, with the reason, and 503 a company node that did not answer.
  • A contract call answers 200 also when it refuses: its status says refused and its problem says what is needed.
  • Each query of an ingested graph writes one line to the central audit: the caller, the graph id and the kind of query, never the question.

Query a context graph

An ingested context graph is a graph a company wrote as JSON, with its own node types and edge types. It is kept with an id such as cg-1cc11e1e, and every query is POST /api/v1/context-graphs/{graph_id}/query with one key in the body. A node is named by its id, its name or another name, in any case. A name that fits several nodes answers 409 with the candidates, and a name that fits none answers 404 with the closest names. relationships is read as another name for edges.

How a written answer is made

For a question, code finds the nodes the question names and the edges around them and numbers them N1 and E1 onwards. The answer model writes an answer only when the model rules allow it for the graph's sensitivity and synthetic flag, and every sentence must cite a given node or edge. A graph with synthetic false never reaches a cloud model. On the development stack the answer model is the stand-in model on the same machine.

Keeping a graph: the JSON

FieldNeededMeaning
graphYesThe name, 3 to 80 characters, one per company
companyYesThe company that owns the data, by id or name. A person writes their own company, a mesh admin any company
nodesYesEach with type and name. If wanted: id (made from type and name when missing), aliases, properties
edgesYes, can be emptyEach with type, source and target (node ids, or names). If wanted: id (made from the type when missing), properties
sensitivityNoPublic, Internal, Confidential or Restricted. Restricted when missing
sharingNocompany (when missing) or group. group needs Internal or Public. A graph of Others needs group
syntheticNofalse when missing, so the data is treated as real. Only a mesh admin writes true
descriptionNoUp to 1,000 characters
graph_idNoThe id of a graph to replace. It keeps its id and its company

When a needed field is missing or wrong, the answer is 422 with problems, one per place to fix, and nothing is kept. The samples in Docs - rpg neuralmesh/01_Inputs_for_Testing/Ingest_Data_Samples show each case.

Uploaded context graphs

A graph made by Upload input lives in the mesh graph. It is read with GET /api/v1/mesh/uploads/graphs/{graph_id}, written out in the JSON structure with POST /api/v1/mesh/uploads/json-templates/render, and its entities are found with the mesh graph search. The query route of ingested graphs does not read it.

Glossary

API
Application programming interface: the routes a program calls to use NeuralMesh.
Route
One method and path of the API, for example POST /api/v1/context-graphs/{graph_id}/query.
Bearer token
A signed text sent in the Authorization header as Bearer and the token. Sign-in gives one that is valid for 12 hours.
Service token
The token of a registered application, with the role context_client. In development it comes from python -m scripts.issue_service_token in app/.
Envelope
The one request body of the context contract: schema_version, tool, purpose, caller and input.
Context contract
The published set of 14 tools that applications call, version 1.1. Its sha256 lets an application see that it changed.
Purpose
Why a call is made: problem_solving, compliance, bid_support, learning, career_mobility or inspection. Company nodes release data by purpose.
Caller
In the envelope, the end user's company (subsidiary), roles and, for a person, an opaque user reference (user_ref).
Status
The first word of a contract answer: ok, partial, no_evidence, blocked, needs_input or refused.
Problem
The part of an answer that says what went wrong and what is needed, with a code such as not_found or invalid_input.
Mesh
The company nodes of the group joined through one central service.
Company node
The MCP server one company runs over its own documents, with its own policy and audit. Ports 8101 to 8108 in development. Not the same as a node of a graph.
Mesh graph
The central graph of entities and links taken from the company nodes and the group vocabulary. It holds no document text.
Entity
One item of the mesh graph: a company, an item, a document, a concept, a skill, a role, an expert or an asset.
Context graph
A named graph of related inputs. Uploaded ones are made by Upload input from files. Ingested ones are written as JSON on Ingest data.
Node
One thing in an ingested context graph, with a type and a name, for example a Supplier named Supplier X.
Edge
One relationship between two nodes, with a type, a source and a target, for example Supplier X SUPPLIES Rotor seal RS-200. The page shows edges as links.
Hop
One edge walked from a node to its neighbour.
Path
A chain of edges that joins two nodes. The path query gives the shortest ones.
Jaccard index
Shared neighbours of two nodes divided by all the neighbours of the two, from 0 to 1. The similar query ranks by it.
Sensitivity
Public, Internal, Confidential or Restricted. A missing one is Restricted.
Sharing
company: only the owning company and mesh admins see an ingested graph. group: every company sees it.
Never-leave
Items shown as metadata only to other companies, such as formulations and pre-results finance.
Synthetic
Data invented for testing. A cloud model may read synthetic data in development only.
Stand-in model
The local model of the development stack. It writes answers from the evidence by fixed rules, with no cloud call.
MCP
Model Context Protocol, the protocol AI agents use to call tools. The gateway serves it as Streamable HTTP.
curl
A command-line program that sends one HTTP request. Each Try entry gives the curl command of its call.
