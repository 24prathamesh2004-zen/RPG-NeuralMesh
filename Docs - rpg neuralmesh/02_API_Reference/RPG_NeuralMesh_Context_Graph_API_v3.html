RPG NeuralMesh: Context Graph API

Five steps to create a graph, ask it and read it. The examples are answers of the running API, recorded on 12 November 2026.

Your application gives NeuralMesh its content as a graph, and then asks that graph. Every call goes to http://127.0.0.1:8000 on the development stack. A body is JSON, sent with Content-Type: application/json.

Step 1: Sign in

Send your email and password once. Keep access_token and send it with every other call as Authorization: Bearer <token>. It is valid for 12 hours.

Request

POST /api/v1/auth/signin

{
 "email": "presenter@neuralmesh.local",
 "password": "<password>"
}

What comes back. access_token, the token for the next calls.

{
 "access_token": "<token>",
 "token_type": "bearer"
}

Step 2: Check your JSON

Send the graph with ?check=true. Nothing is kept. Fix each place listed under problems and send it again, until the answer has no problems.

Request

POST /api/v1/context-graphs?check=true
Authorization: Bearer <token>

{
 "graph": "Example: spare parts of a mixing line",
 "company": "Zensar",
 "description": "Example data, invented to show the JSON structure.",
 "sensitivity": "Internal",
 "sharing": "company",
 "nodes": [
  {
   "id": "plant-a",
   "type": "Plant",
   "name": "Plant A",
   "properties": {
    "city": "Example city"
   }
  },
  {
   "id": "line-1",
   "type": "Line",
   "name": "Mixing line 1"
  },
  "..."
 ],
 "edges": [
  {
   "type": "HAS_LINE",
   "source": "plant-a",
   "target": "line-1"
  },
  "..."
 ]
}

What comes back. The counts of the graph, what was filled in and the defaults used. graph.id is null, because nothing is kept.

{
 "graph": {
  "id": null,
  "name": "Example: spare parts of a mixing line",
  "company_name": "Zensar",
  "nodes": 7,
  "edges": 7,
  "sensitivity": "Internal",
  "sharing": "company"
 },
 "checked_only": true,
 "filled": [
  "7 edge ids made from the type"
 ],
 "defaults": [
  "synthetic: false, so the data is treated as real and no cloud model reads it"
 ]
}

When something has to be fixed, the answer is 422 and names each place

{
 "detail": "The graph was not created: 2 fields need a change.",
 "problems": [
  "company: missing. Write \"company\" with the company that owns the data, for example \"CEAT\".",
  "edges[0]: target \"nowhere\" is not a node of this graph."
 ]
}

Step 3: Create the graph

Send the same JSON without check. The graph is kept.

Request

POST /api/v1/context-graphs
Authorization: Bearer <token>

the same JSON

What comes back. Status 201 and the same answer, now with graph.id, for example cg-1cc11e1e. Keep this id.

Step 4: Ask the graph

Send a question, or one of the six other query kinds, to the graph by its id.

Request

POST /api/v1/context-graphs/cg-1cc11e1e/query
Authorization: Bearer <token>

{
 "question": "Which suppliers supply the rotor seal?"
}

What comes back. The edges that answer the question, and a written answer when the model rules allow one for the graph. If not, answer_note says why.

{
 "answer": "Supplier X SUPPLIES Rotor seal RS-200 [E1]. Supplier Y SUPPLIES Rotor seal RS-200 [E2].",
 "answer_note": null,
 "edges": [
  {
   "ref": "E1",
   "text": "Supplier X SUPPLIES Rotor seal RS-200"
  },
  {
   "ref": "E2",
   "text": "Supplier Y SUPPLIES Rotor seal RS-200"
  },
  {
   "ref": "E3",
   "text": "Seal wear AFFECTS Rotor seal RS-200"
  }
 ]
}

Step 5: Read or change the graph

Read the whole graph by its id. To change it, change this JSON and send it to step 3. It carries its graph_id, so the graph is replaced, not made twice.

Request

GET /api/v1/context-graphs/cg-1cc11e1e
Authorization: Bearer <token>

What comes back. The graph in the same format as you sent it, with its graph_id.

Two kinds of input

InputHow it is sentLimits
Documents (files)Send one folder for your application, with one subfolder for each topic. A mesh admin loads it on the Upload input page. Each subfolder becomes one context graph. No API takes files from another application today..txt, .md, .csv, .json, .pdf or .docx. Up to 20 MB for each file. At least 40 characters of text. A PDF must hold text that can be selected, not a scanned page.
A graph as JSONSend it yourself with the Create API (step 3). One JSON for each topic.Up to 8,000,000 bytes. Up to 5,000 nodes and 20,000 edges. Graph name of 3 to 80 characters. Needed: graph, company, nodes (type, name), edges (type, source, target).

Other limits

WhatLimit
TokenValid for 12 hours. Sign in again after that.
QuestionUp to 2,000 characters.
Answer of a questionUp to 30 nodes and 40 edges.
Answer of a nodes or edges queryUp to 200 nodes and 500 edges.
Real dataA graph without "synthetic": true is treated as real data. No cloud model reads it, so a question gets the nodes and edges without a written answer.

Who may call what

TokenWhat it may do
Mesh admin tokenCreates a graph for any company. Asks and reads every graph.
Company user tokenCreates a graph for their own company. Asks and reads the graphs of their company and the graphs shared with the group.
Application service tokenAsks and reads the graphs shared with the group. It cannot create a graph today.

Fields of the graph JSON

FieldNeededWhat it holdsExample
graphYesThe name of the graph, 3 to 80 characters. A company has one graph of each name."graph": "Example: mixing line spare parts"
companyYesThe company that owns the data, by id or by name. A person writes their own company, a mesh admin may write any company."company": "CEAT"
nodesYesThe list of the things in the graph."nodes": [ ... ]
nodes: typeYesWhat the node is, in the words of the person, for example Supplier."type": "Supplier"
nodes: nameYesThe name of the node."name": "Supplier X"
nodes: idNoA short id the edges use."id": "sup-x"
nodes: aliasesNoOther names of the node, up to 50, each up to 200 characters. A query finds the node by any of them."aliases": ["Mixer 1"]
nodes: propertiesNoValues of the node: text, numbers, true or false, or lists of them. A field written beside type and name is kept as a property too."properties": {"stock": 14}
edgesYes, can be emptyThe list of relationships. relationships is read as another name for edges."edges": [ ... ]
edges: typeYesThe kind of relationship, in the words of the person, for example SUPPLIES."type": "SUPPLIES"
edges: source and targetYesThe node the edge starts at and the node it ends at, by id, or by name when the name fits one node."source": "sup-x", "target": "rs-200"
edges: idNoA short id of the edge."id": "e6"
edges: propertiesNoValues of the edge, the same kinds as on a node."properties": {"preferred": true}
sensitivityNoPublic, Internal, Confidential or Restricted."sensitivity": "Internal"
sharingNocompany: only the owning company and mesh admins see the graph. group: every company sees it, which needs Internal or Public. A graph of Others needs group."sharing": "company"
syntheticNotrue when the data is invented for testing. Only a mesh admin writes true."synthetic": false
descriptionNoA text of up to 1,000 characters."description": "Spare parts of mixing line 1"
graph_idNoThe id of a graph to replace, as Read gives it. Without it a new graph is made."graph_id": "cg-1cc11e1e"

The seven ways to ask

The body of Ask holds exactly one of these.

What it asksBody
What does the graph hold{"overview": true}
Find things by type, name or property{"nodes": {"type": "Supplier", "name": "part of a name", "properties": {"material": "FKM"}}}
One thing and what is around it{"node": "Mixer 1", "hops": 1}
Relationships{"edges": {"type": "SUPPLIES", "source": "Supplier X", "target": "Rotor seal RS-200"}}
How two things are connected{"path": {"from": "Supplier X", "to": "Plant A", "max_hops": 4}}
What is similar to one thing{"similar": {"node": "Supplier X", "top": 5}}
A question in plain words{"question": "Which suppliers supply the rotor seal?"}

Errors

CodeWhat it meansWhat to do
401No token, or the token is expired.Sign in again.
404No graph with this id is shown to your token, or the query names a node that is not in the graph.Check the graph id. For a node, use one of the close names the answer gives.
409The name in the query names more than one node.Send the id of one of the candidates the answer lists.
413The JSON has more than 8,000,000 bytes.Split the graph by topic.
422The JSON or the query body cannot be used. Nothing is kept.Fix each place listed under problems. Places count from 0, so nodes[0] is the first node.

Create a graph from a JSON file in Azure Blob storage

POST /api/v1/context-graphs/from-storage

For a JSON above the 8,000,000 byte limit. You put the JSON file in your Azure Blob container and send its URL with a read-only access signature that expires. NeuralMesh fetches the file, runs the same check as Create and keeps the graph.

Request (sample)

{
 "source_url": "https://<storage account>.blob.core.windows.net/<container>/onboarding_buddy/first_week.json?<access signature>",
 "check": false
}

Answer (sample)

{
 "graph": {
  "id": "cg-<8 characters>",
  "name": "Onboarding: first week",
  "nodes": 4200,
  "edges": 9100
 },
 "use": "/api/v1/context-graphs/cg-<8 characters>/query"
}

Create graphs from a folder of files in Azure Blob storage

POST /api/v1/context-graphs/from-storage-folder

For documents. You put the folder of your application in your Azure Blob container, with one subfolder for each topic and the list file inputs.csv, and send the URL of the folder. NeuralMesh fetches the files, reads each one and makes one context graph for each subfolder.

Request (sample)

{
 "source_url": "https://<storage account>.blob.core.windows.net/<container>/onboarding_buddy/?<access signature>",
 "company": "Zensar"
}

Answer (sample)

{
 "status": "reading",
 "files": 12,
 "graphs": [
  {
   "id": "g-<8 characters>",
   "name": "Leave and attendance",
   "inputs": 2
  }
 ]
}
