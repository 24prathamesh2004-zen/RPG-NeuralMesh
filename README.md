# RPG NeuralMesh

RPG NeuralMesh is a synthetic-data proof of concept for cross-subsidiary knowledge discovery. Each pilot company runs a separate MCP server over its own local knowledge pack. A central FastAPI/LangGraph service fans a question out to the selected nodes, which apply their own exposure policies and return cited evidence. No source records are migrated to a group data lake.

> **POC only:** all included knowledge and demo accounts are synthetic. Local accounts use a development identity flow; do not connect real corporate data or expose the development services publicly.

## Current capabilities

- One node registry, `app/config/nodes.yaml`, read by the API, the orchestrator, the nodes and the pack builder.
- Seven independent subsidiary MCP servers: CEAT (`8101`), KEC (`8102`), Zensar (`8103`), Harrisons Malayalam (`8104`), Raychem RPG (`8105`), RPG Life Sciences (`8106`) and Asvata (`8107`). Seven tools each: `health`, `describe_capabilities` (with packs and a node profile), `search`, `summarize`, `find_experts`, `request_access` and `export_graph` (metadata only, for the mesh service identity).
- 35 knowledge packs (one per subsidiary and domain) built from the synthetic YAML by `knowledge/packgen.py`, validated with the group packs, each with an embedded Chroma store (no server) of the text its node may release. The stores are generated by `python -m knowledge.packgen` and are not kept in git. Node search merges FTS5 keyword search with Porter stemming, vector search (all-MiniLM-L6-v2 through ONNX Runtime) and the routed concepts by reciprocal rank fusion.
- Node-side policy as before, plus a per-datapoint purpose check (`learning` and `career_mobility` added). Every returned item is an evidence record (`app/contracts/evidence.py`, `schema_version` 1.0).
- A central mesh graph (SQLite tables loaded into NetworkX) filled from the group packs and the nodes' exports. Routing resolves concepts by alias and by meaning, so the node choice is optional. Cross-subsidiary links count only after both owners approve them in Governance.
- A context layer in the LangGraph flow: resolve, route, fan out, scope (top 12 documents round-robin by node rank, re-rank that demotes but never drops), expand, build (24,000-character budget), answer, check (seven code rules). A model policy (`app/config/model_policy.json`) allows a cloud model in development only and never for Confidential or Restricted evidence, and strict mode refuses one at start outside development. Model calls are audited without content, and answers are cached by their evidence bundle.
- A context API for SkillForge under `/api/v1/context` and as an MCP gateway on `8100`: `role_context`, `skill_context`, `ask`, `learning_sources`, `find_mentors`, `vocabulary_export`, plus the talent pack import.
- SQLite-backed signup/sign-in, subsidiary membership, and optional consented expert profiles.
- React UI pages for Dashboard, Ask NeuralMesh (automatic routing, answer, links, also-found list), Expert Finder, Mesh Nodes (profiles and the graph), Governance (requests, links between companies, decision log), and Admin. Reviews are simulated for local demo accounts only.

**Answer model:** no model key ships with the repository, so the Ask page and `ask` return the evidence and citations alone, with the reason. For development without a model, `NEURALMESH_MODEL_POLICY=config/model_policy.dev-standin.json` points every step at `evaluations/standin_model_server.py`, a stand-in that composes answers from the evidence by rule and is not a language model. With `NEURALMESH_GROQ_API_KEY` set in development, the answer step runs only for bundles without Confidential or Restricted records, as the model policy requires. Use the `group-gateway` or `local-ollama` entry of the policy file for the rest.

## Start locally on macOS or Linux

From `app/`, with the environment of `app/requirements.txt` active:

```bash
make packs                        # data pack, 19 knowledge packs, vector indexes (needs the all-MiniLM-L6-v2 ONNX model)
bash scripts/dev_stack.sh start   # stand-in model, the registered nodes, the API, the gateway on 8100 and the Vite UI on 5173
make test                         # unit and flow tests
make live-check                   # wiring check against the running services
python -m evaluations.golden_answers   # the ten golden scenarios through the running API
bash scripts/dev_stack.sh stop
```

`make nodes`, `make dev` and `make gateway` start the parts one by one instead. `python -m mcp_nodes <id>` runs any registered node.

`python -m scripts.issue_service_token` prints a development token for SkillForge's service identity.

Since 2026-11-07 the mesh is a context graph platform: graph rules per domain in `app/config/graph`, one intake for every input format, generic context tools and the Snap and Score inspection layer, a similarity job (`make similarity`), the Domains and Applications pages, and `requirements.lock` with a CI workflow. `planning_docs/RPG_NeuralMesh_Implementation_Status.md` lists each part.

The development answer model is Claude (`config/model_policy.json`, entry `claude-dev`, key `NEURALMESH_ANTHROPIC_API_KEY` in `app/.env`). `python -m scripts.check_model` makes one call to prove the key, and `NEURALMESH_MODEL_POLICY=config/model_policy.json bash scripts/dev_stack.sh restart-api` switches the running stack from the stand-in to it. Groq stays as the entry `groq-dev`.

## Prerequisites

- Python 3.11+
- Node.js 20+
- The workspace venv at `../venv` or another environment with `app/requirements.txt` installed

## Start locally on Windows

Run each service in its own PowerShell terminal.

1. Start the API from the repository root:

```powershell
Push-Location app
..\venv\Scripts\python.exe -m uvicorn api.main:app --reload --host 127.0.0.1 --port 8000
```

2. Start the subsidiary MCP servers from `app`, one process per node:

```powershell
..\venv\Scripts\python.exe -m mcp_nodes.ceat
..\venv\Scripts\python.exe -m mcp_nodes.kec
..\venv\Scripts\python.exe -m mcp_nodes.zensar
..\venv\Scripts\python.exe -m mcp_nodes.harrisons
```

3. Start the UI:

```powershell
Push-Location app/ui
npm install
npm run dev
```

Open the Vite URL, normally `http://localhost:5173`.

## Seed presentation data

From the repository root:

```powershell
Push-Location app
..\venv\Scripts\python.exe -m scripts.seed_demo_accounts
```

The development-only seed creates five `@neuralmesh.local` accounts, four opted-in synthetic experts, one pending KEC content request, and one pending CEAT expert-introduction request. It is idempotent and only updates accounts in the reserved demo domain. The shared demo password and account list are documented in [app/scripts/DEMO_ACCOUNTS.md](app/scripts/DEMO_ACCOUNTS.md).

The flagship Ask example is the CEAT-to-Harrisons latex-spoilage question. The included seed data contains approved materials-handling summaries, aggregate spoilage trends, source citations, restricted-data canaries, and policy scenarios.

## Configuration and local state

- API accounts: `app/.neuralmesh/accounts.db`
- Node grants/audits: `app/.neuralmesh/nodes/<node>/`
- Generated synthetic node indexes and structured mock databases: `app/neuralmesh_kb_pack/data_pack/`
- Optional Groq setting: `NEURALMESH_GROQ_API_KEY` in a local `app/.env`; never place the key in the browser or commit it.
- Local runtime databases, `.env` files, virtual environments, `node_modules`, and build output are excluded by `.gitignore`.

## Tests

From the repository root:

```powershell
.\venv\Scripts\python.exe -c "import sys,pytest; sys.path.insert(0,'app'); raise SystemExit(pytest.main(['app/tests','-q']))"
```

Build the frontend from the repository root:

```powershell
npm.cmd --prefix app/ui run build
```
